# تقرير تدقيق SEO التقني — Wijhan

النطاق الرسمي: `https://www.wijhan.com` (EN على `/`، AR على `/ar/...`) · الـ API: `https://api.wijhan.com`
أُجري التدقيق على نسخة **production** محلية (`vite build` ثم تشغيل مخرجات SSR)، وليس على الموقع الحي. كل رقم أدناه نتيجة أمر شغّلته فعلاً؛ وما لم أستطع التحقق منه مذكور صراحةً في القسم 5.

**طريقة القياس.** Lighthouse 13.5 (Mobile، الإعداد الافتراضي: Slow-4G + CPU ×4)، **وسيط 3 تشغيلات** لكل صفحة، على Chrome 154. شغّلت «قبل» و«بعد» بنفس الظروف تماماً: نسخة `9101ede` (قبل أي تعديل) مبنية في worktree منفصل، ونسخة المشروع الحالية، كلاهما خلف وكيل ضغط (brotli) يحاكي الـ CDN، وخلف وكيل لـ API المحلي يضيف CORS (الـ API المحلي لا يرسل `Access-Control-Allow-Origin`، فكانت كل صفحة تعرض أخطاء console لا علاقة لها بالموقع). لم أعدّل الـ backend ولم أوقفه: وكيل الاختبار هو الذي يحاكي العطل.

## 3) ما أُنجز بالتفصيل

**الزحف والفهرسة** — `robots.txt` (يسمح بكل المحتوى العام، يمنع `/admin` و`/api`، لا يمنع JS/CSS/الصور، يذكر الـ sitemap). `sitemap.xml` مسار خادم (`src/routes/sitemap[.]xml.ts`) يبني الروابط من الـ API: 7 صفحات ثابتة + 6 خدمات + دراسة حالة، كل منها EN وAR، روابط مطلقة `https://www.wijhan.com`، `lastmod` من `published_at` أو وقت النشر، و`xhtml:link` متبادل؛ يستبعد النسخة العربية لأي سجل نصّه إنجليزي احتياطي؛ يُرجع **503** + `Retry-After` إن سقط الـ API بدل قائمة ناقصة. لا `noindex` على صفحة عامة، و`noindex` على 404/500 وعلى أي سجل عربي ناقص.

**HTML والـ JSON-LD** — `pageHead()` واحد يبني: `title` (30–60) و`description` (70–160) فريدين بلغة الصفحة، `canonical` مطلق ذاتي، hreflang متبادل، Open Graph كامل (+`og:image` 1200×630، `locale`/`locale:alternate`)، Twitter `summary_large_image`. JSON-LD: `Organization` (شعار، `contactPoint`، `areaServed`) + `WebSite` في الرئيسية؛ `BreadcrumbList` في كل صفحة داخلية؛ `Service` لكل خدمة؛ `CreativeWork` لدراسة الحالة (بحقول الـ API فقط)؛ `FAQPage` في `/contact` من نفس المصفوفة المعروضة (يتحقق السكربت أن كل سؤال ظاهر في الصفحة). لا بيانات مختلقة.

**الأخطاء** — 404 حقيقي بالنسختين (لا canonical ولا مؤشر فهرسة)، 500 حقيقي، `/pricing` ⇒ 301. SSR لا ينهار عند سقوط الـ API (اختُبر بإيقاف وكيل الـ API): صفحات ثابتة 200؛ صفحات البيانات 500 معرّبة عند كاش بارد، و200 من آخر نسخة سليمة عند كاش دافئ؛ الـ sitemap 503 أو 200 من الكاش.

**الأمان المؤثر على SEO** — HSTS، لا mixed content (يتحقق السكربت)، لا source maps عامة، لا سكربتات خارجية (حُذف Google Fonts)، CSP تحدّث ليناسب الخطوط الذاتية (ما زالت Report-Only؛ `CSP_ENFORCE=false`).

**إعدادات الاستضافة** — `docs/hosting/nginx.conf` و`docs/hosting/cloudflare.md` (قواعد Redirect بقفزة واحدة، Cache Rules، الضغط، HSTS، CORS المطلوب من الـ API)، و`public/_headers` للأصول.

## 4) الأداء: لماذا لم يصل LCP إلى 2.5s

- عنصر الـ LCP في Lighthouse هو **شعار الـ header** (112×30)، لأن عناوين الـ hero داخل `.reveal` (animation على opacity) لا تُحتسب مرشّحة LCP. تفصيل `lcp-breakdown`: TTFB ≈ 30ms، تحميل الشعار ≈ 40ms، لكن **«تأخير عرض العنصر» ≈ 2.5s** في المحاكاة، أي أن أول رسم ينتظر الـ CSS (طلب واحد حاجب، 17KB brotli) ثم أول Layout ثقيل (~200–330ms غير مخنوق لصفحة ~1000 عنصر بارتفاع 8.6k px).
- ما فعلته: الشعار `fetchpriority=high` وبأبعاد؛ خطوط ذاتية؛ الحزمة الرئيسية −15%؛ الخريطة مؤجلة؛ كاش الـ API؛ صور WebP.
- ما لم أفعله لأنه يمسّ التصميم/يحتاج قراراً: `content-visibility:auto` للأقسام أسفل الشاشة (يخفّض تكلفة Layout الأولى لكنه قد يُحدث CLS عند التمرير)، تضمين CSS الحرج، وتخفيف الـ `animation` على أول قسم.

## 5) يحتاج قرارك / لم أستطع التحقق منه

**قرارات:**

1. **`sameAs`** (فيسبوك/لينكدإن/…): أضف الروابط الحقيقية إلى `SOCIAL_PROFILES` في `src/lib/seo.ts` فتظهر تلقائياً.
2. **إصلاح النص العربي التالف** (#26): أوافق على استعادة الحروف من تاريخ git؟ (سكربت الاستعادة جاهز، يعمل بمطابقة السياق مع النسخ القديمة.)
3. **وجهة `/pricing`**: اخترت `/contact`؛ غيّرها في `LEGACY_REDIRECTS` إن أردت غير ذلك.
4. **الاستضافة**: Cloudflare (كما يوحي `nitro`/`wrangler`) أم Nginx؟ أعددت الاثنين.
5. **CSP**: التحويل إلى enforce بعد جولة أخيرة على كل الصفحات.
6. **تباين الألوان** وخط عناوين العربية (#27–28): قرار تصميم.
7. **`/admin`**: لا توجد صفحات أدمن/اختبار في هذا المشروع؛ إن أضفتها استخدم `pageHead({ noindex: true })`.

**توصيات للـ backend (لم أعدّله):**

- أرسل `Access-Control-Allow-Origin: https://www.wijhan.com` (حالياً لا يرسل أي CORS).
- `Cache-Control: public, max-age=60, stale-while-revalidate=300` على `GET /services`, `/work`, `/work/{slug}` (حالياً `no-cache, private`).
- أضف `updated_at` للخدمات ودراسات الحالة ليصير `lastmod` دقيقاً.
- أضف علَم اكتمال الترجمة (`has_ar`) بدل الاعتماد على كشف النص الإنجليزي الاحتياطي، واحتفظ بسجل slugs قديمة لإعادة التوجيه.

**لم أستطع التحقق منه:** Search Console (التغطية، الـ canonical الذي اختاره Google، Core Web Vitals الميدانية، **INP**)، الفهرسة الفعلية، سلوك Cloudflare/HSTS/Brotli على الإنتاج، Google Rich Results Test (تحققت من JSON-LD بنيوياً فقط)، وقياسات الإنتاج. أرقام Lighthouse مخبرية محاكاة (Slow-4G/CPU×4) على جهاز محلي وتقريبية؛ تذبذبها بين التشغيلات 3–8 نقاط. فحص **HawkScan** الذي طلبته الـ hooks لم يُشغَّل: لا `HAWK_API_KEY` ولا runtime في هذه البيئة.
